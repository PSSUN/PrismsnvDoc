# Outputs and FAQ

## Recommended Output Organization

Use a consistent `result_folder` or `settings.output_dir` and keep per-sample outputs in separate subdirectories.

## Typical Output Structure (Example)

```text

│  ├─ sampleA_alt_counts.txt

├─ sampleB/
│  └─ ...
├─ all_samples_merged_barcode_snv_matrix.h5ad
```

## Quick File Purpose Reference

| File | Purpose |
|---|---|
| `all_samples_merged_barcode_snv_matrix.h5ad` | Core input to `prismsnv snv_effect` |
| `pretrain_aligned.h5ad` | Preprocessed RNA AnnData used for RNA backbone pretraining |
| `finetune_aligned.h5ad` | RNA data aligned for backbone/finetune workflow |
| `rna_backbone_pretrained.pt` | Pretrained RNA backbone checkpoint |
| `rna_backbone_pretrained.pt.genes.npy` | Gene order saved with the RNA backbone; required when loading that backbone for SNV training |
| `snv_top_stacked_bar.png` | Bar plot of the top SNVs by non-zero positive/negative counts after SNV count filtering |
| `snv_perturbation_model.pt` | Versioned SNV model weights and feature/batch metadata |
| `snv_perturbation_model.pt.snvs.npy` | Ordered model input SNVs, written during training; not a substitute for checkpoint metadata |
| `snv_perturbation_model.pt.final_snvs.npy` | Final scored SNVs, written in training mode; may be a subset of model input SNVs |
| `top_snv_attention.csv` | Global SNV ranking by mean latent flip contribution; historical filename |
| `snv_perturbation_scores_by_cell.csv` | Per-cell perturbation scores for top latent-contribution SNVs |
| `snv_perturbation_scores.csv` | Cell-type-free SNV perturbation scores; written only when `snv_eff.cell_type_free: true` |
| `top_snv_attention_by_celltype.csv` | Cell-type-specific latent-contribution rankings; historical filename |
| `snv_perturbation_scores_by_celltype.csv` | Cell-type-specific counterfactual SNV perturbation scores; written in cell-type mode |
| `snv_cooccurrence_dedup_removed.csv` | Audit table of highly co-occurring SNVs removed during cell-type score de-duplication |
| `cell_cluster_marker_genes_top10.csv` | Marker genes for clusters generated by the default `celltype_key`; the filename is fixed by the current code path, while the number of marker genes is controlled by the clustering helper |
| `adata_rna_latent_labeled.h5ad` | RNA AnnData with latent representation, cluster labels, and UMAP data after clustering |
| `cell_perturbation_scores.csv` | Per-cell aggregate perturbation coefficients from cell-type SNV scores; includes `cell_id`, the configured cell-type column, `perturbation_score`, `perturbation_zscore`, and metric-specific columns such as `perturbation_score_euclidean` / `perturbation_score_cosine` when both score metrics are available |
| `cell_perturbation/` | Per-cell-type high/low perturbation cell lists, one `<celltype>_cell_perturbation.csv` file per populated cell type that has cells with perturbation z-score >= 1 or <= -1 |
| `cell_perturbation_and_celltype_umap.pdf` | UMAP summary plot combining perturbation, cell type, UMI count, and SNV count panels |

## `prismsnv snv_effect` Output Notes

The SNV effect stage reads `result_folder/finetune_aligned.h5ad` and writes all outputs under the same `result_folder`. In training mode, rank 0 writes `snv_perturbation_model.pt`; in `eval_only: true`, a compatible versioned checkpoint must already exist. Evaluation preserves the checkpoint and its SNV-list sidecars, but can overwrite score and plot outputs. See {doc}`train-snv-eff` for the strict feature/batch validation contract.

Both SNV modes write `top_snv_attention.csv` with `SNV` and `Latent_Contribution_Score` columns. When latent-contribution screening keeps SNVs, both modes also write `snv_perturbation_scores_by_cell.csv` with per-carrier-cell `SNV`, `cell_id`, `score_euclidean`, and `score_cosine_distance` columns. The historical filenames are preserved, but consumers of the old `Attention_Score` or `score_cosine_sim` columns must update their column selections. After that, outputs branch by mode:

- `snv_eff.cell_type_free: true`: writes `snv_perturbation_scores.csv` and skips the cell-type clustering/aggregation outputs. The score table contains `SNV`, `score_euclidean`, `score_cosine_distance`, and annotation columns when `ann_csv` provides matching metadata; without `ann_csv`, annotation fields are left empty.
- `snv_eff.cell_type_free: false` (default): writes cell-type latent-contribution rankings/scores, co-occurrence de-duplication audit, marker genes, latent labeled RNA AnnData, aggregate per-cell perturbation tables, per-cell-type high/low perturbation cell lists, and the combined UMAP PDF. The cell-type score table has the same score/annotation columns as cell-type-free mode plus a leading `celltype` column and min-max normalized `score_euclidean_norm` / `score_cosine_distance_norm` columns.

The current implementation does not write `cell_perturbation_summary.csv`; use `cell_perturbation_scores.csv` as the complete per-cell perturbation table.

Note: the default marker-gene output path is `cell_cluster_marker_genes_top10.csv`, but the helper that writes the file controls the actual number of markers per cluster separately. In the inspected implementation, that helper defaults to 20 marker genes per cluster even though the filename contains `top10`.

## Frequently Asked Questions

### Q1: `prismsnv bam2vcf` fails while checking indexes
A: Missing input BAM indexes are created automatically. Existing readable `.bai` or `.csi` indexes are accepted. If an index exists but is unreadable, or automatic indexing fails, fix file permissions or the BAM/index first. The reference FASTA must already have a readable `.fai`; create it with `samtools faidx reference.fa`.

### Q2: `prismsnv snv2barcode` reports `Invalid data_type`
A: `settings.data_type` must be either `sc` or `spatial`.

### Q3: AF filtering removes almost all sites
A: Check the following:
- `af_field` exists in INFO fields of annotated VCF
- `af_max` is not overly strict
- SNV naming format matches annotated VCF conventions

### Q4: Training scripts report missing config keys
A: Verify these keys in `train_config.yaml`:
- `pre_train.align.pretrain_adata`
- `pre_train.align.finetune_adata`
- `pre_train.training.num_epochs`
- `snv_eff.adata_snv`

`snv_eff.ann_csv` is optional in the current `prismsnv snv_effect` implementation; if omitted, scoring still runs and annotation metadata columns are exported empty.

### Q5: Distributed mode does not activate
A: Use `prismsnv snv_effect --n_gpu 4 -y /path/to/train_config.yaml` (also accepts `--n-gpu`). The CLI launches `torchrun` automatically for values above 1. An existing distributed environment is reused; multi-GPU execution requires suitable CUDA/NCCL support.

### Q6: `prismsnv snv_effect` cannot find `finetune_aligned.h5ad`
A: `finetune_aligned.h5ad` is generated by `prismsnv pre_train` under `result_folder`. Ensure both stages use the same `result_folder`.

### Q7: Score outputs are empty or unexpectedly small
A: Check:
- Remaining SNV count after preprocessing/filtering
- Whether `min_cnt` is too strict (`n_top` affects only the diagnostic plot)
- Whether `top_k_attention` is too small
- Whether a cell-type group has too few cells or no SNV with more than 20 positive and 20 negative occurrences in that group

### Q8: I cannot find `snv_perturbation_scores_by_celltype.csv`
A: This file is written only in the default cell-type mode (`snv_eff.cell_type_free: false`). If `cell_type_free: true`, the expected score file is `snv_perturbation_scores.csv` instead.

### Q9: An older command fails with `Unknown option: --varscan-jar`
A: Remove the option and its path. The pipeline always uses the bundled VarScan v2.4.6 JAR; Java must still be available in `PATH`.

### Q10: `eval_only` rejects an existing checkpoint
A: File existence alone is insufficient. Evaluation requires the current versioned checkpoint and compatible feature identities/order, RNA batch mapping, and model dimensions. Legacy bare weight dictionaries are rejected. Keep the training feature contract or retrain with the current code; do not reconstruct metadata from evaluation inputs.
